02 · the retrieval score

The weighting is data, so you can argue with it.

In the paper the retrieval function is code. Here it is a rank expression attached to a search profile — which means you can change how much recency matters, or how much the importance score counts, without touching the simulator.

views/agent_memory.yamlmulti-source RRF
views:
  - name: agent_relevant_memory
    query:
      sources:
        - name: observations
          scope: {collections: [main]}
        - name: plans
          scope: {collections: [plans]}
        - name: reflections
          scope: {collections: [reflections]}
      fuse: {kind: rrf, rank_constant: 60}
what this buys the simulation3 things
one query, three streamsrrf→ observations · plans · reflections

An agent about to act retrieves from what it saw, what it intended, and what it concluded — fused by reciprocal rank rather than a hand-tuned blend.

tunable without coderank AST→ per search profile

Half-life, term weights, and boosts are catalog values. Re-publishing the package re-tunes the whole population.

the same view feeds the promptartifact block→ daily_agent_prompt

Retrieval and prompt assembly share one definition, so what the agent recalls is what the agent is told.

03 · three simulated days

Gossip that leaves a traversable graph.

When an agent relays something it heard, the relayed memory stores a derived_from edge back to the fact it came from. Diffusion therefore stops being “similar text in two places” and becomes a graph you can walk — which is how the paper's interview measurement becomes a query instead of an eyeball.

  • d1
    wake, meet, gossipAgents start with seed memories, plans, and calendars, then trade what they know. Each relay writes a provenance edge, not a copy.
  • ↓
    overnight: reflectThe accumulator has crossed 150 summed importance, so each agent's day becomes cited insight — and every insight opens onto the scored memories under it.
  • d2
    re-plan, meet againPlans are revised from those reflections. The party happens, or it doesn't.
  • m
    measureA paper-style interview measures how far one fact actually diffused, dawn → day 2 — answered from the graph.
  • d3
    distil & open the glass boxThe profile derivation turns each stream into a cited agent summary, and one belief is opened to its roots: the run that wrote it, the resolved model, and the events it fused.

04 · the boundary

Memseek is not the simulator.

This distinction is the reason the example is honest: the interesting generative behaviour stays application code, and it calls its own model. Memseek stores what happened and decides what to recall.

The simulation owns

  • Simulated time, and who is in the same place
  • Who meets whom, and what they say
  • Its own LLM calls for in-character dialogue and planning
  • Deciding to act — memseek never moves an agent

Memseek owns

  • The immutable memory stream and its provenance edges
  • Importance scoring on write, and the fused retrieval score
  • Reflection and profile derivations, with citations required
  • Deterministic prompt assembly with a hashed input manifest

05 · from your app

The simulator's whole memory interface.

Observations in, ranked recall and an assembled prompt out. The example borrows memseek's configured provider seam for its own in-character generation, so the model aliases stay in one place.

simulation.pypublic SDK
# 1 · the agent saw something. importance is scored on write.
await memseek.records.ingest(
    collection="main", type="observation", entity="agent:isabella",
    text="Maria said she is planning a party at Hobbs Cafe on Tuesday.",
    content={"heard_from": "agent:maria"},
    derived_from=[origin_record_id],   # ← makes diffusion traversable
)

# 2 · about to act: recall across observations, plans, reflections
recall = await memseek.search(
    query="what should I do this afternoon?",
    entity="agent:isabella", mode="hybrid", k=12,
    include=["text", "scores", "occurred_at"],
)
for hit in recall["hits"]:
    hit["scores"]["importance"]   # the paper's term, on the record

# 3 · assemble the prompt: summary + schedule + relevant memory
prompt = await memseek.render_artifact(
    "daily_agent_prompt", entity="agent:isabella",
)
prompt["rendered"]                        # hand this to your model
prompt["manifest"]["input_record_ids"]   # exactly what it knew

# 4 · your simulator's own call — memseek is not in this loop
line = await your_model.say(prompt["rendered"], in_character="isabella")
